# 講習站｜教育訓練管理平台 需求說明書 v1

Oct 23, 2026 · @Emily

## 專案概述

「講習站」是一個給單一講師使用的教育訓練管理平台：在行事曆開課、掛上簡報、自動產生課後問卷 QR Code，並在課堂上即時看填答與抽獎。資料存在講師本人的 Google 試算表，網站程式碼中不含任何密碼或可讀取個資的網址。

| 項目 | 內容 |
| --- | --- |
| 使用者 | 講師（單一管理者）、學員（不需登入，掃碼填答） |
| 主要對象 | 學校圖書館講習為主，未來擴及醫院 |
| 簡報來源 | Canva 嵌入連結為主；也支援 PDF 與自製互動網頁簡報 |
| 問卷 | 一套公版問卷，可在後台編輯，有版本控制 |
| 抽獎 | 蒸集姓名與 Email，與問卷答案分開保存，由講師現場抽獎 |

**第一版不做：** 多人帳號與權限分級、自動寄送得獎信、自訂網域、活動照片上傳。這些留待使用穩定後再評估。

介面示意請對照同一份設計畫布「教育訓練管理平台 介面示意」（01～07 共 7 個畫面）。

## 系統架構與技術選型

網站放 GitHub Pages、資料放 Google 試算表、中間用兩個 Apps Script 把關，全部免費，且不需要學新的資料庫後台。

&#91;embedded content: 系統架構 · 公開端與後台分開\]

學員只碰得到左上的公開路徑，它只能寫入、不能讀名單；完整名單只經由下方需要 Google 登入的後台。

| 層 | 選用 | 理由 |
| --- | --- | --- |
| 學員端網頁 | GitHub Pages（純 HTML、CSS、JavaScript） | 免費、不需建置工具、網址固定 |
| 公開 API | Google Apps Script 網頁應用程式 | 與試算表同帳號、免費、可在伺服器端驗證 |
| 講師後台 | Apps Script HtmlService（僅限自己） | 用 Google 登入保護，不需密碼 |
| 資料 | Google 試算表 | 你已熟悉，可直接篩選、匯出 |
| QR Code | qrcode-generator（cdnjs，瀏覽器端產生） | 網址不外傳到第三方服務 |

設計畫布中後台畫面是視覺示意；實際上線後，後台網址會是 Google 的 script.google.com，而不是 GitHub。

規模上限：每場幾百人、每年數十場都在 Apps Script 免費額度內。若未來要開放給整個團隊或大量場次，再評估搬到 Supabase，試算表資料可直接匯入。

## 資料結構

一個 Google 試算表，五個分頁。問卷答案與抽獎登記放在不同分頁，且沒有任何欄位可以把兩者對應起來。

| 分頁 | 主要欄位 | 說明 |
| --- | --- | --- |
| `courses` 課程 | course\_id、title、date、start\_time、org\_name、org\_type（學校／醫院／其他）、location、product\_tags、attendees、status（draft／open／closed）、template\_version、survey\_code、slide\_type、slide\_url、prizes\_json、created\_at、updated\_at | 一堂課一列。survey\_code 是 6 碼隨機代碼，放在問卷網址上 |
| `templates` 公版問卷 | version、status（draft／published／archived）、questions\_json、change\_note、published\_at | 同時只有一個 published、最多一個 draft |
| `responses` 問卷回覆 | response\_id、course\_id、template\_version、submitted\_at、answers\_json | 匿名，不存 IP、姓名、Email |
| `raffle_entries` 抽獎登記 | entry\_id、course\_id、name、email、consent\_at、created\_at、prize、drawn\_at | email 存小寫。prize 留空代表未中獎 |
| `audit_log` 操作紀錄 | time、action、course\_id、detail | 紀錄開關問卷、抽獎、清除資料、發布新版等動作 |

**問卷題目格式（questions\_json）**：每題一個物件，欄位為 `id`、`type`、`label`、`required`、`options`、`maxLength`。type 只允許 `rating`（1–5 分）、`single`、`multi`、`yesno`、`text` 五種。題目 `id` 跨版本沿用，統計才能跨場比較。

**密碼不放在試算表**，放在 Apps Script 的「指令碼屬性」（Script Properties），只有試算表擁有者看得到。

## API 與安全規則

後台用 Google 登入保護，全系統沒有任何一組密碼。做法是把程式拆成兩個 Apps Script 專案：對外的「公開 API」只能寫入與讀取統計數字，「講師後台」設定為只有你的 Google 帳號能開啟。這比 Teso 版的「統一講師密碼」更安全，因為根本沒有密碼可以外洩或被猜。

### A．公開 API（部署對象：任何人）

| 動作 | 輸入 | 回傳 | 規則 |
| --- | --- | --- | --- |
| `getSurvey` | survey\_code | 課名、日期、狀態、題目、獎品 | 不回傳任何回覆或登記資料 |
| `submitResponse` | survey\_code、answers、防機器人欄位、填答秒數 | ok 或錯誤碼 | 只有 open 狀態可寫；依題目定義驗證 |
| `registerRaffle` | survey\_code、name、email、consent | ok 或錯誤碼 | 同課 email 不重複；consent 必為 true |
| `getLive` | survey\_code | 狀態、回覆數、登記數、獎品、已抽出者（遮罩） | 只回傳數字與遮罩姓名 |
| `getViewer` | survey\_code | 課名、簡報類型與網址 | 草稿課程不回傳 |

### B．講師後台（部署對象：僅限自己）

後台整個介面由 Apps Script 的 HtmlService 提供，前端以 `google.script.run` 呼叫伺服器函式。未登入或其他 Google 帳號開啟時，Google 直接拒絕，程式碼不需處理登入。抽獎畫面也放在後台，上課時從你登入的筆電投影。

### 必做的安全細節

1. **寫入前防公式注入**：以 `=`、`+`、`-`、`@` 開頭的文字先加上單引號，避免在試算表裡被當成公式執行。
2. **後台顯示學員文字一律用 textContent**，不用 innerHTML，防止惡意腳本。
3. **伺服器端驗證所有輸入**：題目類型、必填、選項是否存在、文字 ≤ 500 字、姓名 ≤ 30 字、Email 格式。
4. **擋垃圾資料**：隱藏欄位（機器人會填）、填答少於 5 秒拒收、每堂課回覆上限 500 筆。
5. **同時寫入用 LockService 排隊**，避免多人同時送出時資料互相覆蓋。
6. **前端呼叫公開 API 用 POST、Content-Type 設為 text/plain**，以避開瀏覽器跨網域預檢。
7. **公開 API 的程式裡不存在任何讀取姓名或 Email 的函式**，從架構上就沒有可以被挖出的入口。

## 頁面規格

七個畫面分在兩個地方：學員會看到的三頁放 GitHub Pages，其餘四頁在講師後台。編號對應設計畫布。

| # | 畫面 | 位置 | 必要功能 |
| --- | --- | --- | --- |
| 01 | 後台總覽・行事曆 | 後台 | 月曆（上下月、回到今天）；課程依狀態分三種樣式；點課程進詳情；點日期新增課程；本月場次、年度場次、平均滿意度、回收率四個指標；右側「接下來的課」 |
| 02 | 課程詳情 | 後台 | 編輯課程資料；簡報來源三選一（Canva 嵌入、PDF 連結、互動網頁網址）並即時預覽；問卷 QR Code（可下載 PNG）與連結（可複製）；開放／結束填答；即時回覆數、回收率、登記數；獎品設定；最新回覆表格；「在試算表中開啟」；「清除本堂抽獎資料」 |
| 03 | 公版問卷・版本控制 | 後台 | 見下一節 |
| 04 | 學員問卷 | GitHub Pages `/s/?c=代碼` | 手機優先；依題目定義動態產生欄位；必填進度條；送出中動畫；完成後顯示獎品並詢問是否登記抽獎；抽獎表單含同意勾選；已結束的課程顯示「已截止」 |
| 05 | 課堂投影 | GitHub Pages `/live/?c=代碼` | 16:9 大字版面；大 QR Code 與短網址；回覆數、登記數每 15 秒更新；獎品清單；全螢幕按鈕 |
| 06 | 抽獎 | 後台 | 依獎項分頁；一次抽一位、有揭曉動畫；只顯示遮罩姓名與 Email；已中獎者不再抽中；結果寫回試算表，重新整理不會重抽 |
| 07 | 簡報檢視頁 | GitHub Pages `/view/?c=代碼` | 簡報佔滿畫面；底部細欄顯示課名、「顯示回饋 QR」、全螢幕；不需登入、不擋下載 |

**簡報嵌入規則**：Canva 使用其「嵌入」連結（網址含 `?embed`）放入 iframe；PDF 用 Google Drive 預覽連結；自製互動簡報放在同一個 GitHub repo 的 `/decks/` 資料夾。只接受 https 網址。

## 公版問卷與版本控制

每堂課建立時「釘選」當下的公版版本，之後發布新版不會改動已開課的問卷與統計。

**版本規則**

1. 版本狀態只有三種：草稿、使用中、已封存。同時最多一個草稿、一個使用中。
2. 只有草稿可以編輯。要改題目時，從任一版「複製成草稿」。
3. 發布草稿時必填「這一版改了什麼」；版號自動 +1，原使用中版本轉為已封存。
4. 新課程預設套用使用中版本。課程尚無回覆時可改選其他版本；收到第一筆回覆後鎖定。
5. 題目 `id` 跨版本沿用；新題目取下一個未用過的 id，刪除的 id 不再重用。成效統計依 `id` 跨版本合併。
6. 「比較兩版」列出新增、刪除、修改的題目。

**編輯器功能**：新增題目（五種題型）、修改題目文字與選項、切換必填、拖曳排序、刪除、手機預覽。限制：每版 1～15 題；單選與複選 2～20 個選項、每個 ≤ 100 字。

**v1 初始題目**

| id | 題型 | 必填 | 題目 | 選項 |
| --- | --- | --- | --- | --- |
| q1 | rating | 是 | 整體而言，您對本次課程的滿意度？ | 1～5 |
| q2 | rating | 是 | 本次介紹的資源，對您的學習或工作有幫助嗎？ | 1～5 |
| q3 | single | 是 | 課後您會實際使用這個資源嗎？ | 會、可能會、不會 |
| q4 | single | 是 | 您的身分？ | 學生、教師、研究人員、醫護人員、圖書館員、其他 |
| q5 | text | 否 | 想對講師說的話，或希望下次介紹的主題？ | 最多 500 字 |

統計中的「平均滿意度」固定取 q1，「使用意願」取 q3 回答「會」的比例。

## 抽獎流程與個資保護

抽獎資料在領獎完成後由講師清除，只留匿名統計；投影畫面永遠只顯示遮罩後的姓名與 Email。

**流程**

1. 課前在課程詳情設定獎項名稱與數量（可多個獎項）。
2. 上課時開放填答，學員完成問卷後自願登記抽獎。
3. 講師按「結束填答」，名單凍結；未結束前不能抽獎。
4. 進入抽獎畫面，選獎項、按「抽出下一位」。伺服器端從未中獎名單隨機抽出一位並立即寫入 prize 與 drawn\_at。
5. 獎項抽滿後按鈕停用；重新整理畫面只會顯示已存結果。
6. 課後在後台匯出得獎名單 CSV（完整姓名與 Email），自行聯繫領獎。
7. 領獎完成後按「清除本堂抽獎資料」，刪除該課所有姓名與 Email，只保留登記人數與得獎人數。

**遮罩規則**：姓名保留首尾字、中間改 ○（王○明；兩字名為王○）；Email 保留 @ 前兩字與完整網域（mi\*\*\*@gmail.com）。遮罩在伺服器端做完才回傳。

**同意條款（學員端勾選）**：「我同意提供姓名與 Email，僅用於本次抽獎與得獎聯繫，活動結束後 30 天內刪除。」

**提醒機制**：課程結束超過 30 天且抽獎資料未清除時，後台總覽頂端顯示橙色提示條，列出待清除的課程。

**學員端提示**：問卷頁底部注明「問卷不蒸集姓名與 Email，抽獎資料分開保存。請勿填寫病患資料。」

## 視覺與互動規範

深藍為主、橘色只用在「最重要的一個動作」與抽獎相關元素；扁平色塊、清楚格線，不用漸層、毛玻璃與 emoji。

| Token | 色碼 | 用途 |
| --- | --- | --- |
| navy | #12305C | 側欄、主要文字、抽獎背景 |
| blue | #1E5FB4 | 主要按鈕、開放中狀態、重點數字 |
| blue-soft | #E6EEF9 | 標籤底色、已結束課程 |
| ground | #F5F7FB | 頁面背景 |
| line | #D9E2EF | 邊框、分隔線 |
| muted | #5A6B85 | 次要文字 |
| orange | #F28A1E | 主動作按鈕、草稿標記、抽獎；上面的字一律用 navy |
| orange-ink | #B4560A | 白底上的橙色文字（日期、編號） |
| orange-soft | #FFF8F0 | 獎品區塊底色 |

**字型**：中文 Noto Sans TC（400／500／700／900）；數字與英文小標 Outfit（500／700／800）。標題 34–36px 粗體 900，投影畫面主標 76px。

**形狀**：卡片圓角 18–22px、按鈕 12px、標籤全圓。邊框 1px，不用陰影；唯一例外是主按鈕的「實心下緣」（5px 深色底邊，按下時下沉）。

**品牌小符號**：藍色圓角方塊右上角一顆橙色小圓點；同一個「大圓＋小橙點」幾何圖形用在投影、問卷抬頭等空白處做為裝飾。

**小互動（沉穩但可愛）**

- 評分按鈕選中時往上彈 3px，變橙色
- 送出按鈕按下時下沉，送出中顯示三顆小圓點跳動
- 完成頁的勾勾以筆畫動畫畫出，旁邊橙點輕輕彈一下
- 投影畫面數字更新時向上翻動（像計分板）
- QR Code 卡片上的「掃我！」標籤每 6 秒輕晃一次
- 抽獎揭曉：問號卡片翻面成票券，姓名字元逐一彈入
- 所有動畫 ≤ 400ms，並尊重系統的「減少動態效果」設定

**無障礙與裝置**：文字對比至少 4.5:1；可點擊區域 ≥ 44px；學員問卷以 390px 寬手機為主，後台在平板寬度以下側欄收合成上方選單。

## 分階段開發與驗收標準

第一階段做完就能在下一場課使用；每階段驗收通過再進下一階段。

### 第 1 階段：問卷、投影、抽獎

範圍：試算表結構與初始化腳本、公開 API、學員問卷（04）、課堂投影（05）、後台簡易課程列表與課程詳情（02 的問卷、獎品、回覆部分）、抽獎（06）。公版問卷先以 v1 寫入試算表，無編輯器。

- [ ] 用手機掃 QR Code，可在 1 分鐘內完成問卷與抽獎登記
- [ ] 同一堂課用同一 Email 登記第二次會被拒絕，並顯示友善訊息
- [ ] 課程未開放或已結束時，問卷頁顯示對應狀態且無法送出
- [ ] 投影畫面數字在 15 秒內反映新回覆
- [ ] 不登入 Google 開啟後台網址會被拒絕
- [ ] 在瀏覽器開發者工具搜尋公開頁面程式碼，找不到任何可讀取姓名或 Email 的方法
- [ ] 未結束填答時無法抽獎；重新整理抽獎畫面不會重抽；同一人不會中兩次
- [ ] 在文字題輸入 `=1+1` 後，試算表顯示的是文字而非算式結果
- [ ] 「清除本堂抽獎資料」後，試算表內該課已無任何姓名與 Email

### 第 2 階段：行事曆、簡報、公版問卷編輯器

範圍：行事曆（01）、課程詳情完整版含簡報（02）、公版問卷與版本控制（03）、簡報檢視頁（07）。

- [ ] 貼上 Canva 嵌入連結後，課程詳情與檢視頁都能正常翻頁
- [ ] 發布新版公版問卷後，舊課程問卷題目不變、新課程套用新版
- [ ] 已有回覆的課程無法更換問卷版本
- [ ] 「比較兩版」正確列出新增、刪除、修改的題目
- [ ] 行事曆點日期可直接新增課程，日期自動帶入

### 第 3 階段：成效統計

範圍：年度／月份場次、依產品與機構類型分組、滿意度趨勢、使用意願比例、匯出 CSV、30 天清除提醒。

- [ ] 可依產品篩選，得到該產品的場次、觸及人數、平均滿意度
- [ ] 匯出的統計 CSV 不含任何姓名或 Email

## 給 Claude Code 的完整提示詞

使用方式：先把這份文件匯出成 Markdown，存到專案資料夾的 `docs/SPEC.md`；再把下面整段貼給 Claude Code。提示詞只啟動第 1 階段，驗收後再請它進行下一階段。

```text
你是資深全端工程師。請幫我開發「講習站」教育訓練管理平台。完整需求在 docs/SPEC.md，開始前請先讀完它，有與需求衝突或不清楚的地方先問我，不要自行假設。

【關於我】
我不是工程師。所有部署步驟會由我手動操作，請寫成我照做就能完成的中文步驟。當你需要我做任何事（建立試算表、部署 Apps Script、設定 GitHub Pages），請停下來告訴我確切要點哪裡。

【技術限制】
1. 不使用任何建置工具或框架：純 HTML、CSS、原生 JavaScript。GitHub Pages 直接發布資料夾內容。
```

## 實作補充（第 1 階段）

為了符合上文的安全規則，實作時多做了這些，與上文欄位略有不同：

- **網站檔案放在 repo 根目錄**（`s/`、`live/`、`assets/`、`config.js`），不是 `web/`。GitHub Pages 只能從根目錄或 `/docs` 發布。
- **`config.js` 有兩個設定**：`API_URL`（公開 API）與 `ADMIN_URL`（後台，投影頁的抽獎按鈕用）。
- **`courses` 多三欄**：`raffle_count_final`、`winner_count_final`、`raffle_cleared_at`。清除抽獎資料後，用來保留登記人數與得獎人數。
- **`raffle_entries` 多一欄 `email_hash`**：公開 API 檢查 Email 重複時只比對雜湊值，完全不讀姓名與 Email 欄。
- **`getLive` 不回傳得獎者姓名**，只回傳每個獎項已抽出幾位。投影頁不需要姓名，所以公開 API 連遮罩後的姓名都不碰；遮罩姓名只出現在後台抽獎畫面。
- **抽獎登記需要「填完問卷」的一次性憑證**：送出問卷時拿到一張有簽章、6 小時有效的憑證，登記抽獎時繳回，用過就失效。憑證不記錄是哪一份問卷，所以問卷和抽獎名單仍然對不起來；這是為了防止有人跳過問卷、直接呼叫 API 灌抽獎名單。
- **rating 題的 `options`** 放兩端說明文字，例 `["非常不滿意","非常滿意"]`。
- **姓名遮罩**：三字以上一律保留首尾字、中間只放一個 ○（歐陽娜娜 → 歐○娜），不洩露字數。
- **試算表所有欄位設為純文字格式**，避免日期、代碼被自動轉格式。
